## 1. Current-state summary

### What already works
- Deterministic scoring engine (`lib/scoring/engine.ts`) is the single source of truth for thresholds, point tables, and hard stops.
- Canonical Financial Model (`lib/tools/cfm.ts`) + lens registry (`lib/tools/registry.ts`) provide a source-labeled integration contract for Decision Lab tools.
- Local-first sync with server reconciliation exists for finance, advisor threads, and path state.
- Server-side entitlements (`lib/entitlements.ts`) and advisor quotas (`lib/advisor/quota.ts`) are fail-closed.
- Plaid sync is robust: encrypted tokens, cursor discipline, verified webhooks, idempotency.
- Deterministic Companion fallback preserves parity for free tier / outages.

### What is fragmented
- **User experience:** ~19 consumer destinations in nav + 11 quick actions + 18 tool cards. No active decision workspace.
- **Scenarios:** Three independent subsystems (Scenario Studio, Decision Lab lens scenarios, Readiness simulator) with no reconciliation layer.
- **Tool hand-offs:** `ChainLinks.carry` is declared but unused; cross-lens navigation loses context.
- **Data provenance:** Plaid verified data flows to dashboard/path/simulator but is walled off from the CFM/Decision Lab tools.
- **AI safety:** `/api/advisor` has no automated output guardrail; Agent OS reports fake tool execution.
- **Trust/honesty:** `debt-payoff` and `blind-budget` break the source-tag contract.
- **Reproducibility:** Path/scenario IDs are random; simulator anchors to stored scores.
- **Privacy:** Plaid transactions/accounts stored plaintext with no retention bound; bank cash flow sent to Anthropic without recorded consent.

## 2. Target Decision OS architecture

### 2.1 Conceptual spine

```
Active Decision Workspace
    ├── Decision Context          (type, goal, horizon, household, constraints)
    ├── Canonical Reality         (verified, self-reported, derived, illustrative, missing)
    ├── Evidence & Gaps           (required, recommended, optional, completed, skipped)
    ├── Scenarios & Lenses        (futures of this decision, deterministic outputs)
    ├── Deterministic Evaluation  (readiness, verdict, binding constraints)
    ├── Path to Ready             (continuation of verdict)
    ├── Companion Context         (explains deterministic outputs, asks for gaps)
    ├── Receipt                   (versioned snapshot of what was known and concluded)
    └── Outcome Loop              (later calibration without rewriting history)
```

### 2.2 Module mapping (existing → target)

| Existing module | Target role | Notes |
|-----------------|-------------|-------|
| `lib/scoring/engine.ts` | Deterministic evaluation spine | Already correct; protect as source of truth. |
| `lib/tools/cfm.ts` | Canonical reality projection | Extend with Plaid `"plaid_sync"` source label. |
| `lib/tools/registry.ts` | Capability registry | Keep; add orchestration metadata for journey steps. |
| `lib/tools/digest.ts` | Evidence transport to Companion | Keep; ensure every invoked lens publishes one. |
| `lib/decisions/simulate.ts`, `lib/tools/scenarios.ts`, `lib/readiness/scenario.ts` | Scenario futures | Unify assumptions or surface independence explicitly. |
| `lib/readiness/path.ts` | Path layer | Already correct; integrate with active decision. |
| `lib/advisor/*`, `app/api/advisor/route.ts` | Explanation layer | Add output guardrail; preserve deterministic fallback parity. |
| `lib/agents/registry.ts`, `app/api/agents/route.ts` | Specialist framework | Do not expose fake `tools_called`; gate by unlock level. |
| `lib/finance/store.ts`, `lib/plaid/*` | Reality capture | Connect Plaid snapshot to CFM; add consent record. |
| `lib/assessment/*` | Evidence collection | Launch from active decision; result feeds workspace. |
| `components/dashboard/*` | "Today" projection | Reduce to active decision, next best action, and progress. |
| `app/[locale]/(product)/tools/*` | Capability library | Keep for power users / deep links, but demote from primary nav. |
| `app/[locale]/(product)/decisions/page.tsx`, `/scenarios`, `/path` | Workspace views | Bind to active decision context. |

### 2.3 Consumer shell (target)

Primary persistent destinations (hypothesis to prototype):

- **Today** — resume the active decision; one next best action; progress snapshot.
- **Decisions** — list current and past decisions with receipts.
- **Path** — active Path to Ready and progress (when a path exists).
- **Homie** — contextual Companion anchored to the active decision.

Secondary surfaces:
- **Decision Lab** — all lenses/tools, available for exploration and direct deep linking.
- **Profile / Settings** — household, connections, billing, data rights.

Operator/admin surfaces are visually and structurally separated; they do not appear in the consumer header.

### 2.4 Decision orchestration contract (new, lightweight)

Introduce a declarative `DecisionJourney` contract that maps decision types to evidence steps. Each step specifies:

- `stepId`, `decisionTypes[]`
- prerequisites and blocking evidence
- eligibility/skip rules
- tool/lens/agent invoked
- input sources from canonical reality
- completion criteria
- result written back to decision snapshot
- readiness/path/receipt effects
- explanation and transition copy
- analytics event
- entitlement requirement

The orchestrator is deterministic for gating. AI explains, asks adaptive questions, and invokes approved tools; it does not invent state or mark steps complete.

## 3. Implementation roadmap

### Phase 0 — Safety and trust foundation (P0)
These fixes reduce real user harm and compliance exposure and require no product/legal/production decision.

1. **Add output guardrail to `/api/advisor`**
   - Import `sentinelCheck` from `lib/agents/registry.ts`.
   - Apply to model reply before responding.
   - On flag, return deterministic fallback + visible disclaimer.
   - Add regression tests.
   - Files: `app/api/advisor/route.ts`, `__tests__/advisor-sentinel.route.test.ts`

2. **Fix prompt-injection surface in `/api/advisor`**
   - Wrap context blocks in XML delimiters.
   - Escape/strip control characters, backticks, XML delimiters in user-controlled strings.
   - Validate `surface` against `SURFACE_LABELS` server-side.
   - Add prompt-injection regression tests for `identity.name`, `hardStops`, `boardMeetingLine`.
   - Files: `app/api/advisor/route.ts`, `lib/advisor/context.ts`, tests

3. **Remove or rename fake `tools_called` in Agent OS**
   - Option A: rename to `tools_suggested` and document no execution.
   - Option B: remove from response until real executor exists.
   - Files: `app/api/agents/route.ts`, `lib/agents/registry.ts`, tests

### Phase 1 — Finance/decision spine coherence (P1)
4. **Connect Plaid data to CFM with source label**
   - Extend `FieldSource` to include `"plaid_sync"`.
   - Read latest `financial_snapshots` with `source === "plaid_sync"` into CFM.
   - Preserve explicit precedence/conflict UX; never silently override self-reported data.
   - Files: `lib/tools/cfm.ts`, `lib/finance/store.ts`, `lib/plaid/cashflow.ts`

5. **Implement `ChainLinks.carry`**
   - Pass carried values via query params or overlay write-back.
   - Target lens seeds from carried values on mount.
   - Files: `components/tools/ChainLinks.tsx`, `lib/tools/registry.ts`, tool pages

6. **Fix `debt-payoff` and `blind-budget` source-tag honesty**
   - Convert `debt-payoff` to registry inputs + `useLensPrefill` + `LensField`.
   - Add `source` prop to `RangeField` / blind-budget inputs.
   - Files: `app/[locale]/(product)/tools/debt-payoff/page.tsx`, `app/[locale]/(product)/tools/blind-budget/page.tsx`, `components/tools/RangeField.tsx` (or create)

### Phase 2 — Determinism and reproducibility (P1)
7. **Make path/scenario IDs deterministic**
   - Derive IDs from inputs + timestamp hash instead of random UUID.
   - Files: `lib/readiness/path.ts`, `lib/readiness/scenario-path.ts`, `lib/tools/scenarios.ts`

8. **Align hard-stop thresholds**
   - Import `CREDIT_HARD_STOP` and engine thresholds into preflight and advisor route.
   - Files: `lib/readiness/preflight.ts`, `app/api/advisor/route.ts`

### Phase 3 — Active Decision Workspace (P2)
9. **Introduce lightweight decision-orchestration contract**
   - Define `DecisionJourney` type and a homebuying reference journey.
   - Files: `lib/decisions/journey.ts`, `lib/decisions/types.ts`

10. **Build "Today" view prototype**
    - Refactor dashboard to show active decision, next best action, and progress.
    - Files: `app/[locale]/(product)/dashboard/page.tsx`, `components/dashboard/TodayView.tsx`

11. **Collapse consumer nav**
    - Reduce `APP_PRIMARY_NAV` + `APP_MORE_NAV` to Today / Decisions / Path / Homie + Decision Lab secondary.
    - Files: `lib/layout/app-nav.ts`, `components/layout/AppHeader.tsx`

### Phase 4 — Scenario reconciliation and receipts (P2)

    - Add explicit assumption diff and reconciliation warnings.
    - Files: `lib/decisions/simulate.ts`, `lib/tools/scenarios.ts`, `lib/readiness/scenario.ts`

## 4. Reference vertical slice

The first implementation slice should exercise the full OS spine for the homebuying decision:

1. User lands on **Today** and sees/resumes active homebuying decision.
2. System identifies missing evidence (e.g., no finance data).
3. User connects or enters finance reality once; source-labeled.
4. System invokes the relevant lens (e.g., affordability) inside the workspace.
5. Lens seeds from CFM; user adjusts; explicit scenario saved.
6. Deterministic result updates readiness/verdict; shows what changed.
7. Companion explains the result and points to the unresolved step.
8. Next best action leads to assessment or path generation.
9. Path to Ready is generated from verdict.
10. Receipt captures snapshot, assumptions, and conclusion.

## 6. Blockers requiring human decision

1. **Plaid data in CFM precedence:** Should Plaid-synced numbers become the default source in tools, or should users explicitly approve each use?
2. **Agent OS fake tools:** Remove `tools_called` from API response, or invest in real tool-calling executor?
3. **Transaction retention window:** What is the maximum analytic window HōMI needs? (Proposed: 120 days.)
4. **Bank data → Anthropic consent:** What disclosure copy and consent UX is acceptable?
5. **Consumer shell names:** Are Today / Decisions / Path / Homie acceptable, or should they be different?
6. **Legal review:** Any consumer-reporting/fair-lending implications before lender-facing score workflows?
